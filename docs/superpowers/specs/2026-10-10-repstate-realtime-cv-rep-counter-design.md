# Repstate: Browser Real-Time Pose Rep Counter — Design

Date: 2026-10-10
Status: Approved design, pre-implementation
Target: New standalone open-source repository (not inside this portfolio repo). This spec and the implementation plan live here until the new repo exists; copy both into the new repo at bootstrap.

## 1. Purpose

Public, verifiable proof of the real-time computer-vision and finite-state-machine claims in the portfolio headline (MediaPipe pose pipeline, deterministic FSM rep engine, adaptive frame rate, reliability under live analysis). All production evidence for those claims is employer-private. This project reproduces the engineering pattern in the open, with reproducible benchmark numbers.

Success criteria:

- A recruiter can open the live site, allow the camera, do squats or push-ups, and see correct rep counts with a live FPS/latency HUD.
- A reviewer can run `pnpm test` and see exact rep counts asserted against recorded landmark fixtures.
- The README shows a benchmark table (accuracy, FPS p50/p95, inference ms, device) that was produced by the in-app `/benchmark` page and can be regenerated by anyone.
- Lighthouse 90+ on the landing route.

## 2. Scope

In scope (v1):

- Exercises: squat, push-up.
- Live camera mode and bundled-clip replay mode.
- Deterministic engine with unit tests on recorded landmark fixtures.
- In-app benchmark page with JSON export.
- Static deployment on Netlify.

Out of scope (v1): accounts, any server state, Web Worker/OffscreenCanvas pipeline, npm publishing of the engine, form-quality scoring, mobile app, additional exercises.

## 3. Stack

- TanStack Start (file routes, static prerender), React 19, TypeScript strict, Tailwind CSS 4, Vite.
- shadcn/ui (`radix-nova` style) for every UI element that has a shadcn equivalent; Hugeicons through a single `components/ui/icons.tsx` wrapper.
- Feature-first layout: `src/features/<feature>/{domain,application,infrastructure,ui}` with one-way dependencies `ui → application → domain`; `infrastructure` implements `application` ports. Layer boundaries enforced by ESLint.
- `@mediapipe/tasks-vision` PoseLandmarker (GPU delegate, CPU fallback). Model file served from `public/models/`, not fetched from a CDN at runtime.
- Vitest for engine and pipeline unit tests. Playwright for one smoke test.
- Netlify static deploy; no server functions used.

## 4. Architecture

Feature `rep-counter` with four layers and one-way dependencies: `ui → application → domain`, and `infrastructure` implementing `application` ports (`PoseDetector`, `FrameSource`, `FrameScheduler`). `domain` (the engine) imports nothing from the DOM, React, or MediaPipe; `application` (the session use-case, adaptive budget, perf tracking) is unit-tested with fakes. Section headings below keep the original names (`engine`, `pipeline`, `routes`) for the concepts; the implementation plan maps them to the layered folders.

### 4.1 `src/engine/` (pure TypeScript, deterministic)

Input per frame:

```ts
type Landmark = { x: number; y: number; z: number; visibility: number };
type Frame = { t: number /* ms, monotonic */; landmarks: Landmark[] /* 33, MediaPipe order */ };
```

Output: events, returned synchronously from `step(frame)`:

```ts
type EngineEvent =
  | { type: 'state'; from: State; to: State; t: number }
  | { type: 'rep'; count: number; t: number; durationMs: number }
  | { type: 'warning'; code: 'low_visibility' | 'no_pose'; t: number };
```

States: `IDLE`, `READY`, `DOWN`, `UP`, `LOST`.

Exercise definition:

```ts
type ExerciseDef = {
  id: 'squat' | 'pushup';
  joints: [number, number, number][]; // angle triples (left and right side), MediaPipe indices
  downAngle: number;   // enter DOWN when angle <= downAngle
  upAngle: number;     // enter UP when angle >= upAngle (hysteresis gap: upAngle > downAngle)
  minDwellMs: number;  // must hold DOWN this long before UP can count
  minVisibility: number; // mean visibility of used joints below this => LOST
};
```

Squat: hip–knee–ankle (indices 23/24, 25/26, 27/28). Push-up: shoulder–elbow–wrist (11/12, 13/14, 15/16). Angle = the smaller of left/right side angles when both visible; the visible side when only one passes the visibility gate.

Transition rules:

- `IDLE → READY`: first frame with visibility ≥ gate and angle ≥ `upAngle`.
- `READY → DOWN`: angle ≤ `downAngle`.
- `DOWN → UP`: angle ≥ `upAngle` AND time in DOWN ≥ `minDwellMs`. Emits `rep`.
- `UP → READY`: immediately on next frame (UP is a one-frame state so UI can flash it).
- `DOWN → READY` (no rep): angle ≥ `upAngle` but dwell not met. No rep, no warning; only the state event is emitted.
- Any state `→ LOST`: visibility < gate for 3 consecutive frames. Counter frozen.
- `LOST → READY`: visibility ≥ gate for 3 consecutive frames AND angle ≥ `upAngle`. A rep in progress before LOST is discarded.

Angle smoothing: exponential moving average, alpha 0.5, applied before thresholds. Reset on LOST.

The engine is a class `RepEngine(def)` with `step(frame): EngineEvent[]`, `reset()`, and a read-only `snapshot()` returning `{state, count, angle, lastRepAt}`. No timers, no globals. Same frame sequence always yields the same events.

### 4.2 `src/pipeline/` (browser)

- `createSource(kind: 'camera' | 'video', el)`: wraps a `<video>` element; camera via `getUserMedia({video: {facingMode: 'user', width: 640, height: 480}})`.
- `createDetector()`: loads PoseLandmarker in VIDEO running mode with GPU delegate; on failure retries with CPU delegate and records which one is active.
- `runLoop({source, detector, engine, onFrame, onPerf})`: uses `video.requestVideoFrameCallback` (falls back to `requestAnimationFrame`). Per callback: if `now - lastInferenceAt < budgetMs` skip inference (count as dropped); else run `detectForVideo`, build `Frame`, call `engine.step`, call `onFrame({landmarks, events, snapshot})`.
- Adaptive frame budget, two axes:
  - Load axis: rolling window (last 30) of inference durations; `budgetMs = max(1000/targetFps, p90(inferenceMs) * 1.2)`. Keeps the main thread responsive on slow devices instead of queueing.
  - Activity axis: `targetFps` is 30 while the engine is `READY`/`DOWN`/`UP` and 10 while it is `IDLE`/`LOST` (nobody in position; save battery). Driven purely by engine state.
- Rendering is decoupled from inference. The loop stores the latest landmarks in a ref; the overlay draws them on its own `requestAnimationFrame` loop at display rate (60 Hz on most screens) regardless of how often inference runs. The HUD reports `renderFps` and `inferenceFps` separately. This is the public demonstration of "60 FPS rendering with adaptive inference".
- Perf samples every 500 ms: `{renderFps, inferenceFps, inferenceP50, inferenceP95, dropped, delegate}`.
- Frame-skip logic lives in a pure function `shouldInfer(now, lastAt, window, targetFps)` so it is unit-testable with a fake clock.

### 4.3 `src/routes/` (TanStack Start)

- `/` — landing text (what it proves, how) and the live demo: camera permission button, exercise selector (squat/push-up), `<canvas>` skeleton overlay on the video, large rep count, state badge, HUD (render FPS, inference FPS, inference p50/p95 ms, dropped, delegate). "Use sample clip instead" link when camera is denied.
- `/benchmark` — replays bundled clips `public/clips/squat-10.webm` and `public/clips/pushup-10.webm` (10 ground-truth reps each, ~20–30 s, recorded by the author). Shows per-clip: detected count vs ground truth, render FPS, inference FPS, inference p50/p95, dropped, delegate, UA, hardware concurrency. "Export JSON" button downloads the results; "Copy README row" copies a Markdown table row.
- `/how-it-works` — FSM state diagram (static SVG), angle definitions, thresholds, dwell, hysteresis explanation, link to engine source and fixtures.

### 4.4 Fixtures

`fixtures/landmarks/<clip>.json`: array of `Frame` recorded from the bundled clips using a dev-only recorder on `/benchmark` (`?record=1` adds a "Download landmarks" button). Each fixture ships with `<clip>.meta.json` `{groundTruthReps, exercise, recordedWith: {model, delegate, date}}`. Fixtures are committed so CI never needs MediaPipe, a GPU, or video decoding.

## 5. Benchmark Proof

Two independent layers, both reproducible by a third party:

1. **CI (Vitest):** for each fixture, feed frames into `RepEngine`, assert `count === groundTruthReps`, assert no two `rep` events closer than `minDwellMs`, snapshot the state sequence. Also a throughput test logging engine frames/second over the fixture (expected far above 10k fps; purpose is to show engine cost is negligible).
2. **Browser (`/benchmark`):** same clips through the real MediaPipe pipeline. Numbers are device-dependent by nature; the README table therefore records device and delegate next to each row, and the export JSON is committed under `benchmarks/<date>-<device>.json`.

README claims are limited to what these two layers show. No claim of "99.9%" is written unless a fixture-based measure supports it (e.g., 0 false reps across N fixture frames).

## 6. Error Handling

- Camera denied / unavailable → inline message, switch to sample-clip mode in one click.
- Model load failure (network/WASM) → error panel with retry; page remains usable for `/how-it-works`.
- GPU delegate init failure → automatic CPU fallback, HUD shows `CPU` badge.
- Low visibility / no pose → engine `LOST`, overlay shows "Step back so hips and knees are visible" (per exercise copy), counter frozen, never increments.
- Tab hidden → loop pauses (`visibilitychange`), resumes without resetting count.

## 7. Testing

- `engine`: fixture tests (above); synthetic tests for hysteresis (angle oscillating inside the gap must not count), dwell (fast bounce must not count), LOST discard (rep in progress across LOST is dropped), smoothing reset, left/right side selection.
- `pipeline`: `shouldInfer` with fake clock (budget respected, window updates, fallback to 30 fps floor).
- Playwright smoke: open `/benchmark`, run squat clip, assert count element shows `10`. Runs in Chromium with CPU delegate; marked `allow-fail` on CI if headless WebGL is unavailable, but must pass locally.
- Lighthouse CI on `/` with 90+ budget for performance, accessibility, best practices, SEO.

## 8. Accessibility and UX Basics

- All controls keyboard-operable with visible focus.
- Rep count announced via `aria-live="polite"` region (count only, not every state).
- Reduced-motion respected for the UP flash.
- Light/dark theme follows system.
